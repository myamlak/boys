# Papers evidence bundle

This directory carries the measurement harnesses, small summary records and data manifests for four
evidence sets that use the Boys function kernel. It carries no manuscript text, plan, decision record
or review document. Raw per-cell data is too large for the repository; where it is excluded, its
SHA-256 digest is recorded in a manifest named in the relevant section.

All four sets were produced against the same library revision:

| Field | Value |
| --- | --- |
| Boys version | 5.0.0 |
| Tag | `v5.0.0` |
| Commit | `482fd3388c276091834a6c12a642d9de2481c9f2` |
| Working tree | clean at capture |

The per-set provenance record that states this revision is listed in the table below. One set also
records the revision of the papers working tree at capture; the other three recorded the Boys
revision only.

## A. Amplification sweeps

Two sweeps share one set of helper modules.

- `amplification_form/` measures the amplification of a seed perturbation. `sweep2.cpp` writes
  `paths.csv`, `cells.csv` and `admission.csv`; `analyze.py` reads them and writes `per_order.csv`,
  `prediction.csv`, `prediction_scan.csv`, `band_summary.csv` and `summary.txt`.
- `product_amplification/` measures the product form. `sweep1.cpp` writes `cells.csv`,
  `admission.csv` and `replica_gain.csv`; `analyze.py` writes `per_order.csv`, `band_summary.csv`,
  `decomposition.csv`, `growth.csv`, `gain_up.csv` and `summary.txt`.
- `common/reference.py` builds the high-precision reference; `common/boysprovenance.py` writes
  `provenance.json`, including the library revision, compiler flags and the digest of every Boys
  header and reference grid the run read. `common/replica.hpp` is included by both harnesses.
- `grid.py` and `fits.py` build the argument grid and the seed fits. `run.ps1` runs each sweep end
  to end and refuses a Boys tree that is not clean at tag `v5.0.0`.

Reproduction (from either sweep directory, in a Visual Studio developer shell with `python` and
`mpmath` available):

```
powershell -ExecutionPolicy Bypass -File run.ps1 -BoysTree <boys-checkout-at-v5.0.0>
```

`run.ps1` writes `data/`, `build/` and `results/`. The `product_amplification` script ends with a
table-generation step that is not part of this directory; every measurement output is written
before that step.

Excluded here and listed with its digest in the sweep's `MANIFEST.sha256`:

| Sweep | Excluded files |
| --- | --- |
| `amplification_form` | `data/grid.csv`, `data/fits.csv`, `data/fits_validation.txt`, `data/reference.csv`, `data/reference_validation.txt`, `results/paths.csv`, `results/cells.csv`, `results/transfer_cells.csv` |
| `product_amplification` | `data/documented.csv`, `data/grid.csv`, `data/reference.csv`, `data/reference_validation.txt`, `results/cells.csv`, `results/replica_gain.csv` |

The manifests list every file under `data/` and `results/` in the captured tree, both the records
kept here and those excluded. The data files are regenerated byte for byte by the commands in
`run.ps1`; the excluded cell and path files are regenerated by the two harness executables.

## B. Accuracy-claim audit

This set has two parts: a claim enumeration and a timing wave.

- `documented-claims-v5.tsv` is the claim enumeration: one documented accuracy statement per line,
  with the document and location, the figure and scope, a status, and the gate row or book that
  registers it. It is an enumeration record, not output of the accuracy gate.
- `wave-5run-v500/` carries the five-repetition timing harness and the record of the run made on
  2026-10-20 (`repeat/context.txt` records the tree revision, instrument digests, host and load
  average; `repeat/canary.log` records the drift canary readings). The two timed instruments are
  `benchmark-far-exp` and `benchmark-gate-exp`, built from the pinned tree. `pool-5run-v500.py`
  aggregates the repetition files; it refuses to pool without the canary readings.
- `wave-5run-v500.sh` is the wrapper; `repeat-5run-v500.sh` runs the repetitions;
  `rebuild-instruments-v500.sh` rebuilds the two instruments; the two `run-selfcheck-*.txt` files
  are the instruments' self-check output.

Tool provenance. The wave records were produced by `benchmark-far-exp` and `benchmark-gate-exp` and
pooled by `pool-5run-v500.py`. The Boost.Math and crlibm part of this evidence set is the MPFR and
mpmath harness, not the Boys accuracy gate: its reference is MPFR 4.2.2 driven through a Ziv loop,
with an independent mpmath check at 400 digits and glibc libm as a third route. The scripts that ran
those three checks were not part of the material supplied for this deposit and are not included
here; `documented-claims-v5.tsv` and the wave harness and record are what this directory carries for
this set. None of the Boost.Math or crlibm checks was produced by `boys-accuracy-gate`.

Reproduction. The scripts carry the recorded run's base directories at the top (`B`, `TREE` and
`RUN` in `repeat-5run-v500.sh`; `D` in the wrapper and pooler). Point them at a local instrument
build and run:

```
bash wave-5run-v500.sh 5
```

The wrapper writes `wave-5run-v500.log` and fills `repeat/`; the pooler can also be run alone:

```
python3 pool-5run-v500.py 5 repeat
```

The wave expects a quiet machine and an instrument build made from the pinned Boys tree. The canary
and the lock rules are part of the scripts.

## C. Coefficient-count sweep

- `count_sweep.py` reads the committed coefficient table (`--static`) or measures stored counts
  against a target over a width sweep (`--sweep`), using the library's own generator for every fit
  and evaluation. `results/static_counts.json`, `results/sweep_all.json`,
  `results/sweep_rel_1e-13.{json,csv}` and `results/sweep_abs_5e-14.{json,csv}` are its records.
  `results/sweep_all.json` carries the same run's metadata block with the Boys commit and tag.
- `results-sensitivity/sweep_all.json` and `results-sensitivity/sweep_rel_1e-14.{json,csv}` are the
  same measurement at the wider target.
- `stability_save_verify.py` runs the stability pass over the accepted rows and writes
  `results-stability/pass_2026-10-20.json`; `cold_ladder.py` re-solves the row named in the pass
  record and writes `results-stability/followup_cold_ladder_2026-10-20.json`. The two `smoke_*.json` files
  are its smoke records. The pass's cache is recomputable and is not included.

Reproduction (from this directory, with `mpmath` available):

```
python count_sweep.py --static --boys-root <boys-checkout-at-v5.0.0> --out results/static_counts.json
python count_sweep.py --sweep --boys-root <boys-checkout-at-v5.0.0> --out-dir results
python stability_save_verify.py --plan
python stability_save_verify.py --out results-stability/save_verify_batch.json
python cold_ladder.py
```

Use `--boys-root` with a local checkout; the script's default points at the machine that produced
the record. `--plan` prints the width grid and the exact commands without running a fit.

## D. Composition audit

`measure_interaction.cpp` is the measurement driver. It emits the narrowed per-lane argument grid,
reads the reference, and writes the per-cell CSV and an environment record. `gen_reference.py`
builds the reference with `mpmath`. `summarise_interaction.py` reads the cell CSV and writes
`summary.json`. `compare_stability.py` compares the configurations and writes `stability.json`.
`selftest_summarise.py` and `selftest_stability.py` are the harness self-tests.
`run_measurement.ps1` and `run_measurement.sh` run the driver, reference generation and summary on
MSVC and GCC.

The result trees are:

| Directory | Configuration |
| --- | --- |
| `results/` | MSVC, fused multiply-add |
| `results-msvc-separate/` | MSVC, separate multiply-add |
| `results-gcc-fused/` | GCC, fused multiply-add |
| `results-gcc-separate/` | GCC, separate multiply-add |
| `results-smoke/` | smoke run, MSVC |
| `results-smoke-separate/` | smoke run, MSVC, separate multiply-add |

The four full trees store `summary.json.gz`. Each is about 4.9 MB uncompressed and is gzipped to
stay under the per-file cap; `gzip -d summary.json.gz` restores the file whose digest is the
`summary.json` line in the same directory's `manifest.sha256`. `results-smoke/summary.json` is
small enough to store uncompressed. Each `environment.txt` records the Boys revision and, where
the driver captured it, the papers-tree revision and dirty state; the full trees record
`papers_revision=4948032c19ecf9eac86daa88f2903291f2ab0dba` and a clean papers tree.

Excluded from each full result tree: `cells.csv` (about 163 MB), `arguments.csv` and
`reference.csv`. Their SHA-256 digests are in that directory's `manifest.sha256`, which is included.
The smoke trees' CSV inputs are excluded on the same rule.

Reproduction (from this directory; the driver scripts select the build type and output directory):

```
powershell -File scripts/run_measurement.ps1 -CoordinatorSignal -BoysSource <boys-checkout-at-v5.0.0>
bash scripts/run_measurement.sh --coordinator-signal
```

The driver emits `arguments.csv`, generates `reference.csv`, runs the canary, then writes
`cells.csv`, `environment.txt` and `summary.json`. For a single step:

```
python scripts/gen_reference.py --arguments results/arguments.csv --out results/reference.csv
python scripts/summarise_interaction.py --cells results/cells.csv --out results/summary.json
```

`compare_stability.py --run <dir> --run <dir> --out results-stability/stability.json` needs the
`arguments.csv` of each run; regenerate it with `measure-interaction --emit-arguments <csv>` first.
The self-tests run without arguments:

```
python scripts/selftest_summarise.py
python scripts/selftest_stability.py
```

## Size and storage

The directory is under 20 MB in total and no stored file exceeds 5 MB. Four summary records are
gzipped, as noted in section D. Everything else is stored as produced. A `.gitattributes` file in
this directory exempts the record files (`*.csv`, `*.json`, `*.log`, `*.sha256`, `*.tsv`, `*.txt`)
from the repository-wide line-ending conversion, because the manifests publish digests over their
exact bytes; source files follow the repository rule.
